CFAACREDIT/FINANCIAL ANALYSIS AUTOMATION · AGENT DESIGN

Agent design: a credit team that reads and writes, while code does the math

How the AI analysts are organized, what each one sees and produces, how they hand off work, and how they are kept accurate and inexpensive. Includes one real run traced from the token log.

Design principle. Deterministic, tested code does all calculation: spreads, ratios, scorecard, S&P-style anchor, peer medians, stress tests and data-integrity checks. The AI agents only read (filing text, statement labels) and write (analysis and narrative). Every quote an agent makes must appear in the source, and every number it writes must appear in its brief. Failed checks are sent back to the agent; after 3 attempts the task escalates to the Manager.

1. Organization and handoffs

Amber = AI agent; blue = code and data; green = code checks applied to every agent output; red dashed = escalation path. Credit, Macro and Micro run in parallel. The Manager reviews once (no back-and-forth) and decides what to do with each escalation: use the partial result, drop it, or ask the user.

Model and why

  • Model: gpt-6-luna through Portkey (PORTKEY_API_KEY), set in one place and changeable with OPENAI_MODEL.
  • Structured output: JSON-schema output (PydanticAI NativeOutput). The course model does not accept function tools, and schemas make every output checkable by code.
  • Reasoning effort low: the agents interpret computed facts rather than solve problems, so low effort keeps hidden reasoning tokens down without hurting quality.
  • No tool calls, no web access: agents can't fetch data or take actions; code decides what they see. This removes a whole class of prompt-injection and runaway-loop risks.

3. Guardrails

Accuracy
  • Quote check: an Accounting quote not found in the filing is rejected and retried.
  • Number check: any number not in the brief (years, notes and small counts excepted) is rejected and retried.
  • A rating is never produced by AI; ratings come only from the scorecard code.
Loops and escalation
  • Each task: 1 try + 2 retries with the specific problems fed back = 3 attempts maximum.
  • After 3 failures the task escalates to the Manager, which decides use-partial / drop / ask-user.
  • Failed attempts' tokens are counted too, so budgets stay honest.
Cost
  • Per-run budget 40,000 tokens: later tasks are skipped if reached.
  • App-wide daily ceiling of 400,000 tokens; per-visitor rate limits.
  • Result cache by brief: unchanged inputs cost 0. Comparisons reuse cached company work.
Prompt injection
  • Filing and upload text is screened; sentences that read like instructions are removed before any agent sees them.
  • Agents have no tools, so injected text cannot trigger an action.
  • Browser inputs are re-validated on the server against allow-lists.
